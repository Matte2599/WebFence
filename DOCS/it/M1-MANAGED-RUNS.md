# M1 — Run gestite e revoca locale

[English](../en/M1-MANAGED-RUNS.md) · [Store progetti](M1-PROJECT-STORE.md) · [Laboratorio HTTP](M1-AUTHORIZED-LAB.md) · [Roadmap](../ROADMAP.md)

`storage.Store.BeginRun(ctx, projectID)` rilegge la **revisione corrente** dello store e registra una `ManagedRun` prima di restituirla. La run espone uno `Scope()` immutabile e un `Context()`; chi la usa deve chiamare `Close()` alla fine. Una dichiarazione scaduta non avvia una run. La scadenza interrompe il contesto e rimuove la registrazione.

Un rinnovo, anche se amplia il perimetro, una revoca esplicita o la cancellazione del progetto fermano tutte le run registrate per quell'ID. Anche `Store.Close()` le ferma. `Store.RevokeAuthorization(ctx, id, expectedRevision)` registra una **nuova revisione revocata** nello schema SQLite corrente v4: dopo la riapertura, `BeginRun` continua a negare l'avvio. Solo `ReviseAuthorization` con una nuova dichiarazione completa, confermata e non scaduta può riattivare il progetto. La revoca delle run precede il commit della modifica: se il commit fallisce, una run può fermarsi senza che la modifica sia stata salvata, scelta conservativa. Una dichiarazione non valida o un conflitto rilevato prima del commit non fermano run valide. La nuova revisione può avviare nuove run soltanto dopo il commit; quelle precedenti ricevono `project_authorization_revoked`.

Lo scope gestito incorpora il contesto di revoca. `transport.NewAuthorizedLab` lo osserva per interrompere DNS, dial, attesa e lettura e lo controlla prima di ogni hop, anche se un chiamante passa al broker un contesto separato. Una richiesta già inviata non può essere ritirata dal server: la cancellazione impedisce nuovo lavoro applicativo e scarta il risultato incompleto. I test con server `httptest` solo loopback coprono richieste in corso e in coda, rinnovo, nuova revisione, revoca esplicita persistente, cancellazione, chiusura dello store e scadenza. Non sono state eseguite scansioni su target esterni.

**Limite di sicurezza:** il registro delle run attive è in memoria e vale per **una istanza di `Store` nello stesso processo**. `Project.BeginRun()` e gli scope non gestiti esistono ancora per i test offline: non offrono revoca dello store. La GUI M1 usa soltanto `RunCrawl` con run gestita. Il lock OS impedisce a un'altra istanza di aprire lo stesso DB; run lasciate aperte dopo arresto vengono segnate `interrupted` alla riapertura, senza riprendere richieste. Processi con archivi diversi non sono coordinati. La modalità pubblica con IP fissati esiste, ma non è stata provata su rete pubblica reale. [Verifica M1](M1-VALIDATION.md).
