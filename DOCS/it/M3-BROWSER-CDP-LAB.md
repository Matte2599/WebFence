# M3 — Laboratorio Linux CDP con origine HTTP

[English](../en/M3-BROWSER-CDP-LAB.md) · [ADR-016](ADR-016-LINUX-CDP-TRIAL.md) · [Stato M3](M3-VALIDATION.md)

`experiments/m3-cdp-browser` è una fixture Linux opzionale, non una funzione della GUI. Richiede Go, Docker e Chromium **solo nel container di prova**. Non accetta URL né target esterni. Il programma genitore passa soltanto il percorso assoluto di Chromium al proprio helper; quest'ultimo applica limiti e seccomp prima di avviare Chromium. Le pipe CDP e tutte le risposte sono locali. La pagina `http://site.test/app/` carica uno script, esegue `fetch('/api')`, richiede un'immagine esterna e segue un redirect verso un'altra origine: le ultime due richieste sono intercettate e negate. Il programma fallisce se mancano eventi attesi, se il browser non eredita il filtro o se supera i limiti del protocollo.

Prova Linux AMD64 nel job CI e prova locale ARM64 del 27 settembre 2026: compilare con `CGO_ENABLED=0 go build -tags=m3cdplab -o /tmp/webfence-m3-cdp ./experiments/m3-cdp-browser`; creare l'immagine con `docker build -f experiments/m3-cdp-browser/Dockerfile -t webfence-m3-cdp-lab .`; eseguire il binario montato come `/wf-cdp` nel container senza rete, in sola lettura, con `/tmp` temporaneo, utente 1000, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--memory 1g` e `--pids-limit 128`. Il comando completo e versionato è nel job `m3-cdp-lab-linux` della CI. Il test locale ARM64 è passato con questi limiti; la CI del branch e di `main` vanno verificate separatamente.

La prova preserva l'origine HTTP nelle richieste del browser e nega la rete autonoma sul percorso sperimentale. **Non** collega il browser al gate/broker WebFence, non prova HTTPS o login e non dimostra una sandbox sicura per pagine non fidate: Chromium usa `--no-sandbox` solo qui, il container è parte del confine di prova e il filesystem del browser non è mediato. Restano aperte le quote aggregate fuori dal container, gli altri OS, la GUI e la prima voce M3.
