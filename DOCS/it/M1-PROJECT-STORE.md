# M1 — Store locale dei progetti

[English](../en/M1-PROJECT-STORE.md) · [Progetto e autorizzazione](M1-PROJECT-AUTHORIZATION.md) · [ADR SQLite](ADR-004-STORAGE-SIGNATURE.md) · [Roadmap](../ROADMAP.md)

`internal/storage` realizza la persistenza M1 con SQLite. Il desktop ora lo usa per progetti e osservazioni redatte; non contiene credenziali, traffico grezzo, report firmati o copie del sito. Per il perimetro verificato vedere la [matrice M1](M1-VALIDATION.md).

## Contratto implementato

`storage.Open(ctx, path)` richiede un percorso assoluto il cui genitore esiste già e crea un file nuovo con permessi `0600` sui sistemi Unix. Rifiuta file non regolari e, su Unix, file esistenti accessibili a gruppo/altri. La GUI usa la directory `WebFence` sotto la cartella di configurazione dell'utente. Un lock OS permanente in `projects.sqlite.lock` impedisce due processi sullo stesso DB; il file lock non va eliminato manualmente. La directory deve essere su filesystem locale affidabile; restano da verificare ACL Windows e corse di symlink su host reali. Gli errori pubblici sono codici senza percorso o dati di progetto.

Lo schema **v4** comprende `projects` (identità, nome e revisione corrente), `authorization_revisions` (dichiarazioni e stato di revoca immutabili), `authorization_origins` (origini canoniche), `scan_runs` e `scan_visits` (codici e conteggi redatti). Il riferimento all'autorizzazione è testo descrittivo, non il documento originale; rimane comunque metadato potenzialmente sensibile **in chiaro**. `CreateProject` inserisce la revisione 1 in una transazione; un ID già presente è rifiutato. `LoadProject` e `ListProjects` restituiscono soltanto la revisione corrente. `ListAuthorizationRevisions` restituisce dati storici descrittivi. Una dichiarazione scaduta o revocata resta leggibile, ma `BeginRun` rifiuta nuove run. `DeleteProject` elimina revisioni, origini, run e visite tramite foreign key; non è cancellazione fisica sicura di pagine, WAL o backup separati.

`ReviseAuthorization(ctx, id, expectedRevision, change)` richiede una **nuova dichiarazione esplicita**, confermata e non scaduta, con proprietario, riferimento e insieme completo di origini. Una transazione aggiunge la revisione e sposta il puntatore corrente solo se coincide con `expectedRevision`; un editor che lavora su una versione superata riceve `storage_revision_conflict`. Un rinnovo può partire da un progetto già scaduto o revocato. `RevokeAuthorization(ctx, id, expectedRevision)` aggiunge invece una revisione non avviabile senza cancellare la cronologia; una seconda revoca è rifiutata. Non si modificano le revisioni precedenti e lo snapshot di una run esistente non acquisisce origini o scadenze nuove. Per le run registrate sullo stesso store, [BeginRun e la revoca locale](M1-MANAGED-RUNS.md) fermano il lavoro precedente alla nuova revisione. Un progetto caricato con `LoadProject` e avviato direttamente con `Project.BeginRun()` non è registrato.

All'apertura vengono controllati versione, tabelle richieste, `quick_check` e chiavi esterne; un database sconosciuto o con versione più nuova è rifiutato. Le connessioni usano WAL, `synchronous=FULL`, foreign key attive, `trusted_schema=OFF` e timeout di lock finito. La v4 nasce atomicamente da un file vuoto; i database v1/v2/v3 migrano a v4 in transazione. Una run rimasta `running` alla riapertura diventa `interrupted` con copertura limitata. `StartScanRun`, `AppendScanVisit` e `FinishScanRun` ammettono solo codici di osservazione noti, mai URL o errori arbitrari; sono consentite 100 run per progetto e 256 visite per run. Una run crawler persistente alla volta impedisce la somma di budget concorrenti nell'istanza. SQLite limita il file principale a 64 MiB; WAL e backup possono consumare spazio aggiuntivo. `Backup(ctx, path)` usa `VACUUM INTO` verso un file privato nuovo, rifiuta un backup durante una scansione e non sovrascrive file esistenti.

## Limiti e prossimi passi

La GUI M1 crea, seleziona ed elimina progetti, configura una origine/un seed per scansione e legge le run salvate dopo riavvio. Non offre ancora rinnovo/revoca, pulsante di backup o ripristino guidato; le API Go esistono. Non copiare un DB aperto ignorando WAL/SHM: usare `Backup`. La cancellazione non rimuove backup esterni né garantisce sovrascrittura forense. Nessuna scansione esterna è stata eseguita per queste prove. I gate su workstation e accessibilità reali restano [aperti](M1-VALIDATION.md).
