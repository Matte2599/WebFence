# M3 — Linux CDP lab with HTTP(S) origin

[Italiano](../it/M3-BROWSER-CDP-LAB.md) · [ADR-016](ADR-016-LINUX-CDP-TRIAL.md) · [ADR-017](ADR-017-CDP-BROKER-BOUNDARY.md) · [ADR-019 HTTPS](ADR-019-CDP-HTTPS-BOUNDARY.md) · [ADR-020 Landlock](ADR-020-CDP-LANDLOCK-BOUNDARY.md) · [M3 status](M3-VALIDATION.md)

`experiments/m3-cdp-browser` is an optional Linux fixture, not a GUI feature. It needs Go, Docker and Chromium **only inside the trial container**. It accepts no URL or external target. For each HTTP and HTTPS variant, the parent creates a synthetic project/run and loopback target, binds scope/path and budgets to the gate and broker with a pinned IP, opens eight connections to the authenticated Unix proxy and passes them to the helper. The helper applies limits and seccomp before starting Chromium. CDP uses inherited pipes; every intercepted request is served through the proxy on preconnected sockets. The page `http(s)://site.test:<port>/app/` loads a script, calls `fetch('/app/api')`, requests an outside image and reaches an endpoint redirecting outside the origin. The gate blocks the image; the broker stops the redirect. The program also checks events, counts, redacted observations, inherited filtering, protocol limits and `isSecureContext` in the HTTPS variant.

After the redirect, the script starts a slow `fetch`. The target signals its start to the parent, which revokes the run lifecycle while the request is in flight. Cancellation closes the target request; the proxy returns 502 and denies the subsequent `fetch` with 403, without another target contact. For each variant, the target sees five requests in total, the broker charges five, and admitted completed observations remain at three. This is a repeatable in-page revocation trial for a **synthetic page**, not proof of revocation for every operation in a product browser.

The HTTPS variant uses an ephemeral certificate for `site.test`, trusted only by the loopback fixture broker; the helper sends absolute-form HTTPS URLs over the Unix socket without `CONNECT`. The broker verifies TLS and hostname before returning the intercepted response to the renderer. Separate tests reject a wrong hostname and outside origin without target contact, and reject absolute HTTPS on the TCP listener. The certificate and private key are created in memory for the trial and are not saved in the repository.

Before starting Chromium, the helper also tries to reach a test TCP listener on `127.0.0.1` already opened by the parent: it requires `EPERM`, including when the container uses `bridge` networking. The CI job runs both HTTP(S) variants with `--network none` and `--network bridge`, without external targets. In a local diagnostic build with only the filter call removed, this check failed: the negative result is sensitive to the filter's presence. It does not by itself prove every renderer path harmless; the browser inherits the filter installed before it starts.

The parent also creates a synthetic private file in a separate temporary directory. The helper reads it before confinement, then applies [Landlock](ADR-020-CDP-LANDLOCK-BOUNDARY.md) on the thread that starts Chromium and requires `EACCES` for reads and writes. A child must be able to read a file in the helper's private directory but not the denied one. The policy permits reading/execution of system directories needed by Chromium and writing only in the private directory; it fails if Landlock ABI 3 is unavailable. This broadens the local negative trial without proving general filesystem isolation.

The follow-up trial uses the same Chromium process after the HTTP(S) fixture: it disables `Fetch` interception only for two `file://` navigations to local synthetic plaintext files. Chromium must load and show the contents of the file in the private directory, then return `net::ERR_ACCESS_DENIED` for the outside file. The parent requires both outcomes alongside the HTTP(S) counters. A temporary diagnostic build without the Landlock call failed the second check because Chromium no longer returned the access error; the diagnostic change is absent from versioned code. This verifies a path through the browser itself but not the absence of every filesystem bypass.

Linux AMD64 CI trial and local ARM64 trial on September 27, 2026: build with `CGO_ENABLED=0 go build -tags=m3cdplab -o /tmp/webfence-m3-cdp ./experiments/m3-cdp-browser`; build the image with `docker build -f experiments/m3-cdp-browser/Dockerfile -t webfence-m3-cdp-lab .`; run the binary mounted as `/wf-cdp` in the container without networking, read-only, with temporary `/tmp`, user 1000, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--memory 1g` and `--pids-limit 256`. The complete versioned command is in the `m3-cdp-lab-linux` CI job. Forty local ARM64 repetitions passed with these limits; with 128 PIDs, one repetition exhausted threads while starting Chromium. Branch and `main` CI need separate checks.

The trial preserves HTTP(S) origin in browser requests, denies autonomous networking and narrows file access on this experimental path. It does **not** test public HTTPS navigation or login or prove a safe sandbox for untrusted pages: Chromium uses `--no-sandbox` here only, the container is part of the trial boundary, and `/proc` and `/dev` remain readable. Revocation in a desktop runtime, aggregate quotas outside the container, other OSs, the GUI and the first M3 item remain open.
