# M1 — Managed runs and local revocation

[Italiano](../it/M1-MANAGED-RUNS.md) · [Project store](M1-PROJECT-STORE.md) · [HTTP lab](M1-AUTHORIZED-LAB.md) · [Roadmap](../ROADMAP.md)

`storage.Store.BeginRun(ctx, projectID)` reloads the store's **current revision** and registers a `ManagedRun` before returning it. The run exposes an immutable `Scope()` and a `Context()`; callers must call `Close()` when done. An expired declaration cannot start a run. Expiry cancels the context and removes the registration.

Renewal, even when it expands scope, explicit revocation or project deletion stops all registered runs for that ID. `Store.Close()` stops them too. `Store.RevokeAuthorization(ctx, id, expectedRevision)` records a **new revoked revision** in current SQLite schema v4: after reopening, `BeginRun` still denies a new run. Only `ReviseAuthorization` with a fresh, complete, confirmed and unexpired declaration can reactivate the project. Run revocation precedes the change's commit: if the commit fails, a run may stop even though the change was not saved, a fail-closed choice. An invalid declaration or a conflict detected before commit does not stop valid runs. The new revision can start new runs only after commit; previous runs receive `project_authorization_revoked`.

The managed scope embeds its revocation context. `transport.NewAuthorizedLab` watches it to interrupt DNS, dialing, waiting and body reads, and checks it before each hop, even if a caller passes the broker an unrelated context. A request already sent cannot be recalled from the server: cancellation prevents further application work and discards an incomplete result. Loopback-only `httptest` cases cover in-flight and queued requests, renewal, the new revision, persistent explicit revocation, deletion, store close and expiry. No external target was scanned.

**Security limit:** the active-run registry is in memory and covers **one `Store` instance in one process**. `Project.BeginRun()` and unmanaged scopes still exist for offline tests and do not provide store revocation. The M1 GUI uses only `RunCrawl` with a managed run. The OS lock prevents another instance from opening the same DB; unfinished runs are marked `interrupted` at reopen without resuming requests. Processes using separate stores are not coordinated. Public mode with pinned IPs exists but has not been tested on a real public network. [M1 verification](M1-VALIDATION.md).
