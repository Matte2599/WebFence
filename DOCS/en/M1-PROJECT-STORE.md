# M1 — Local project store

[Italiano](../it/M1-PROJECT-STORE.md) · [Project and authorization](M1-PROJECT-AUTHORIZATION.md) · [SQLite ADR](ADR-004-STORAGE-SIGNATURE.md) · [Roadmap](../ROADMAP.md)

`internal/storage` implements M1 persistence with SQLite. The desktop now uses it for projects and redacted observations; it contains no credentials, raw traffic, signed reports or site copies. See the [M1 matrix](M1-VALIDATION.md) for the verified scope.

## Implemented contract

`storage.Open(ctx, path)` requires an absolute path with an existing parent directory and creates a new file with `0600` permissions on Unix. It rejects non-regular files and, on Unix, existing files accessible to group/others. The GUI uses `WebFence` under the user's configuration directory. A persistent OS lock in `projects.sqlite.lock` excludes a second process using the same DB; do not remove the lock file manually. The directory must be on a trusted local filesystem; Windows ACLs and symlink races still need real-host review. Public errors are codes without paths or project data.

Schema **v4** comprises `projects` (identity, name and current revision), `authorization_revisions` (immutable declarations and revocation state), `authorization_origins` (canonical origins), `scan_runs` and `scan_visits` (redacted codes/counts). The authorization reference is descriptive text, not the original document; it remains potentially sensitive metadata **in plaintext**. `CreateProject` inserts revision 1 in one transaction; an existing ID is rejected. `LoadProject` and `ListProjects` return only the current revision. `ListAuthorizationRevisions` returns descriptive history. An expired or revoked declaration remains readable, but `BeginRun` rejects new runs. `DeleteProject` cascades through revisions, origins, runs and visits; it is not secure physical erasure of pages, WAL or separate backups.

`ReviseAuthorization(ctx, id, expectedRevision, change)` requires a **new explicit**, confirmed and unexpired declaration with owner, reference and the full origin set. One transaction appends the revision and moves the current pointer only when it matches `expectedRevision`; a stale editor receives `storage_revision_conflict`. An expired or revoked project can be renewed. `RevokeAuthorization(ctx, id, expectedRevision)` instead appends a non-runnable revision without deleting history; a second revocation is rejected. Previous revisions are not modified, and an existing run snapshot cannot acquire new origins or expiry. For runs registered on the same store, [BeginRun and local revocation](M1-MANAGED-RUNS.md) stop previous work before the new revision. A project loaded with `LoadProject` and started directly with `Project.BeginRun()` is not registered.

Opening checks the version, required tables, `quick_check` and foreign keys; an unrelated database or newer version is rejected. Connections use WAL, `synchronous=FULL`, enabled foreign keys, `trusted_schema=OFF` and a bounded lock timeout. Version 4 is created atomically from an empty file; v1/v2/v3 databases migrate to v4 in a transaction. A run left `running` at reopen becomes `interrupted` with limited coverage. `StartScanRun`, `AppendScanVisit` and `FinishScanRun` accept only known observation codes, never URLs or arbitrary errors; 100 runs per project and 256 visits per run are allowed. One persistent crawler run at a time prevents concurrent budgets from accumulating in an instance. SQLite caps the main file at 64 MiB; WAL and backups can use additional space. `Backup(ctx, path)` uses `VACUUM INTO` to a new private file, refuses backup during a scan and does not overwrite existing files.

## Limits and next steps

The M1 GUI creates, selects and deletes projects, configures one origin/seed per scan and reads saved runs after restart. It does not yet offer authorization renewal/revocation, a backup button or guided restore; Go APIs exist. Do not copy an open DB while ignoring WAL/SHM: use `Backup`. Deletion does not remove external backups or guarantee forensic overwrite. No external target was scanned in tests. Real-workstation and accessibility gates remain [open](M1-VALIDATION.md).
