# M1 — Local project store

[Italiano](../it/M1-PROJECT-STORE.md) · [Project and authorization](M1-PROJECT-AUTHORIZATION.md) · [SQLite ADR](ADR-004-STORAGE-SIGNATURE.md) · [Roadmap](../ROADMAP.md)

`internal/storage` implements the **first M1 metadata persistence** with SQLite. It is a Go core component: the desktop does not call it yet and does not save operator projects. It contains no credentials, scan results, evidence, reports or site copies.

## Implemented contract

`storage.Open(ctx, path)` requires an absolute path with an existing parent directory and creates a new file with `0600` permissions on Unix. It rejects non-regular files and, on Unix, existing files accessible to group/others. The caller chooses and protects the directory on a trusted local filesystem; the API does not yet choose the app data directory or solve every symlink race or Windows ACL issue. Public errors are codes without paths or project data.

Schema **v3** separates `projects` (identity, name and current revision), `authorization_revisions` (immutable declarations and revocation state) and `authorization_origins` (ordered canonical origins per revision). The authorization reference is descriptive text, not the original document; it remains potentially sensitive metadata **in plaintext** in SQLite. `CreateProject` inserts revision 1 in one transaction; an existing ID is rejected. `LoadProject` and `ListProjects` return only the current revision from a consistent read. `ListAuthorizationRevisions` returns descriptive history, including revocation state, not runnable scopes. An expired or revoked declaration remains readable, but `BeginRun` rejects new runs. `DeleteProject` cascades through all revisions and origins; it is not secure physical erasure of pages, WAL, backups or future artifacts.

`ReviseAuthorization(ctx, id, expectedRevision, change)` requires a **new explicit**, confirmed and unexpired declaration with owner, reference and the full origin set. One transaction appends the revision and moves the current pointer only when it matches `expectedRevision`; a stale editor receives `storage_revision_conflict`. An expired or revoked project can be renewed. `RevokeAuthorization(ctx, id, expectedRevision)` instead appends a non-runnable revision without deleting history; a second revocation is rejected. Previous revisions are not modified, and an existing run snapshot cannot acquire new origins or expiry. For runs registered on the same store, [BeginRun and local revocation](M1-MANAGED-RUNS.md) stop previous work before the new revision. A project loaded with `LoadProject` and started directly with `Project.BeginRun()` is not registered.

Opening checks the version, required tables, `quick_check` and foreign keys; an unrelated database or newer version is rejected. Connections use WAL, `synchronous=FULL`, enabled foreign keys, `trusted_schema=OFF` and a bounded lock timeout. Version 3 is created atomically from an empty file; v1 and v2 databases migrate to v3 in one transaction, retaining existing declarations as active. Synthetic tests cover both migrations, reopening, revision conflicts, renewal after expiry and revocation, history, unchanged snapshots, cascading delete, rollback halfway through insertion, incompatible schemas, tampered records and context cancellation. CI runs the race-enabled suite on its configured native platforms.

## Limits and next steps

This is **configuration persistence**, not the complete M1 workflow. IT/EN project management UI, cross-process run coordination, disk quotas, verified backup/recovery, run data and results, stopping future jobs and removing their artifacts before deletion, evidence files and removal of all app-managed copies remain open. The local filesystem and permissions/ACLs on each real system need dedicated trials. Do not copy an open database without accounting for WAL/SHM; backup strategy is a separate block. No external target was scanned for these tests.
