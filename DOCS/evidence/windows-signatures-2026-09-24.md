# M0 — Firme dei sorgenti Windows / Windows source signatures

[Sorgenti IT](../it/M0-WINDOWS-SOURCES.md) · [Sources EN](../en/M0-WINDOWS-SOURCES.md) · [Matrice IT](../it/M0-VALIDATION.md) · [Matrix EN](../en/M0-VALIDATION.md)

## Italiano

**Prova locale del 2026-09-24; CI del codice in attesa.** Gli otto input `SKIP` della [raccolta precedente](windows-vcs-2026-09-24.md) sono firme distaccate di FreeType, GCC, gettext, libiconv, libjpeg-turbo, PCRE2, zlib e Zstandard. La versione e la ricetta di ogni pacchetto sono vincolate al manifest dei binari. Il nuovo registro `packaging/windows/source-signature-lock.json` (SHA-256 `b564628c28e34588d8a9f1aa655c7c204cbe94d40f300c24e4ef3e05e598f761`) lega ciascun archivio, payload, firma, fingerprint primario e della sottochiave, file pubblico e fonte di recupero. Sette chiavi pubbliche minimizzate sono conservate in `packaging/windows/source-signing-keys`; gettext/libiconv condividono una chiave. Non sono state inserite chiavi private nel repository.

Le chiavi sono state recuperate tramite gli endpoint HTTPS di keys.openpgp.org o del keyserver Ubuntu, identificandole **per fingerprint completo già dichiarato nelle ricette MSYS2**; i loro byte sono poi fissati nel repository. Il verificatore rifiuta un fingerprint diverso, confronta firma e payload con gli SHA-256 degli archivi conservati, controlla che `.SRCINFO` consenta la chiave primaria e usa una directory GnuPG temporanea isolata. `gpg --verify` non recupera chiavi dalla rete. GCC e PCRE2 firmano con sottochiavi i cui fingerprint e chiavi primarie sono entrambi controllati. La prova locale è stata eseguita in un container GnuPG 2.2.40 con rete disabilitata.

La [raccolta ricostruita](windows-signatures-2026-09-24/source-materials.json), SHA-256 `4c4300e08553cc607aa562c84eff04b1bf3ead13a2f2f93f83fc44a511c050be`, usa gli stessi **21 archivi/316.641.108 byte** e le stesse ricette della raccolta precedente. Ora riporta **112 input `verified`**, otto con prova OpenPGP, e nessun input non verificato per il piano esaminato. Il [nuovo allegato](windows-signatures-2026-09-24/attachment.json), SHA-256 `d71205f3af17eb157dc76a9a961b9dcf2494a8ad75e9555c1baf4dfb9b7a10e9`, include lock e chiavi e ricontrolla tutte le prove. La vecchia raccolta con firme non verificate viene rifiutata senza pubblicare un allegato. **73 test Python locali** superati con GnuPG isolato, inclusa una fixture sintetica con payload alterato. Archivi originali, tar temporanei e chiave privata della fixture restano fuori Git.

La [prima CI sul codice `2417662`](https://github.com/Matte2599/WebFence/actions/runs/35945431893) ha individuato due difetti di portabilità nella nuova prova: su Windows il checkout converte i fine riga di chiavi e fixture, cambiando gli hash; su macOS l'importazione GnuPG fallisce nella directory temporanea lunga. Il commit correttivo mantiene quei file byte per byte nel checkout, usa su macOS un percorso temporaneo corto per il socket GnuPG e include il dettaglio dell'errore GnuPG nella diagnosi. La suite locale di 73 test passa di nuovo; la CI della correzione è in attesa.

**Limiti:** la firma valida attesta che un payload è stato firmato dalla chiave pubblica con il fingerprint fissato dalla ricetta; l'origine delle chiavi da keyserver non prova autonomamente l'identità dei firmatari o la fiducia nella ricetta. Non sono state verificate firme PGP dei pacchetti binari, completezza dei componenti incorporati, licenze o desktop reali. `distribution_ready=false` e `corresponding_sources_complete=false`; M0-02 e M0-06 restano aperti.

## English

**Local trial on 2026-09-24; changed-code CI pending.** The eight `SKIP` inputs in the [previous collection](windows-vcs-2026-09-24.md) are detached signatures for FreeType, GCC, gettext, libiconv, libjpeg-turbo, PCRE2, zlib and Zstandard. Each package version and recipe is bound to the binary manifest. The new `packaging/windows/source-signature-lock.json` (SHA-256 `b564628c28e34588d8a9f1aa655c7c204cbe94d40f300c24e4ef3e05e598f761`) binds each archive, payload, signature, primary and subkey fingerprints, public-key file and retrieval source. Seven minimized public keys are retained in `packaging/windows/source-signing-keys`; gettext/libiconv share one key. No private keys were added to the repository.

Keys were retrieved from the HTTPS endpoints of keys.openpgp.org or the Ubuntu keyserver, identified **by the full fingerprint already declared in the MSYS2 recipes**; their bytes are then pinned in the repository. The verifier rejects a different fingerprint, compares signatures and payloads with SHA-256 values from retained archives, checks that `.SRCINFO` permits the primary key and uses an isolated temporary GnuPG home. `gpg --verify` does not retrieve keys from the network. GCC and PCRE2 sign with subkeys whose fingerprints and primary keys are both checked. The local trial ran in a GnuPG 2.2.40 container with networking disabled.

The [reconstructed collection](windows-signatures-2026-09-24/source-materials.json), SHA-256 `4c4300e08553cc607aa562c84eff04b1bf3ead13a2f2f93f83fc44a511c050be`, uses the same **21 archives/316,641,108 bytes** and recipes as the previous collection. It now records **112 `verified` inputs**, eight with OpenPGP evidence, and no unverified inputs in this reviewed plan. The [new attachment](windows-signatures-2026-09-24/attachment.json), SHA-256 `d71205f3af17eb157dc76a9a961b9dcf2494a8ad75e9555c1baf4dfb9b7a10e9`, includes the lock and keys and rechecks all evidence. The older collection with unverified signatures is rejected without publishing an attachment. **73 local Python tests** passed with isolated GnuPG, including a synthetic tampered-payload fixture. Original archives, temporary tar files and the fixture private key remain outside Git.

The [first changed-code CI run for `2417662`](https://github.com/Matte2599/WebFence/actions/runs/35945431893) exposed two portability defects in the new check: Windows checkout converted line endings in keys and fixtures, changing their hashes; macOS GnuPG import failed in a long temporary directory. The corrective commit preserves those files byte-for-byte at checkout, uses a short temporary path for the macOS GnuPG socket and includes GnuPG error detail in diagnostics. All 73 local tests pass again; CI for the correction is pending.

**Limits:** a valid signature establishes that a payload was signed by the public key with the recipe-pinned fingerprint; obtaining keys from keyservers does not independently prove signer identity or trust in the recipe. PGP signatures on binary packages, embedded-component completeness, licenses and real desktops have not been verified. `distribution_ready=false` and `corresponding_sources_complete=false`; M0-02 and M0-06 remain open.
