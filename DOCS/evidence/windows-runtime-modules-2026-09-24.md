# Windows packaged runtime modules / Moduli runtime del pacchetto Windows

[Roadmap](../ROADMAP.md) · [Matrice IT](../it/M0-VALIDATION.md) · [EN matrix](../en/M0-VALIDATION.md) · [Static PE inventory](windows-pe-import-inventory-2026-09-24.md)

## Italiano

Nel test dello ZIP Windows estratto, `scripts/test-windows-package.ps1` campiona i moduli del processo durante il `--soak-test=10s` con backend Qt `offscreen` e `windows`, dopo aver tolto MSYS2/Go dal `PATH`. Ogni percorso sotto il bundle deve comparire nell'inventario delle 43 DLL o essere `webfence.exe`; il test richiede Qt6Core/Gui/Widgets e il plugin della piattaforma corrispondente. I percorsi fuori dal bundle e dalla directory Windows sono registrati per revisione. `Process.Refresh()` precede ogni lettura dei moduli, perché [la documentazione .NET](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.refresh?view=net-10.0) specifica che le informazioni del processo possono essere in cache.

Il primo tentativo [`18c223a`, run 35950725323](https://github.com/Matte2599/WebFence/actions/runs/35950725323) ha superato i test applicativi, ma il controllo moduli non ha osservato `qoffscreen.dll` e ha fatto fallire il job Windows. Dopo l'aggiunta di `Process.Refresh()` e la stampa dell'inventario prima delle asserzioni, [CI `a9a8e5c`, run 35951514939](https://github.com/Matte2599/WebFence/actions/runs/35951514939) ha superato tutti e sei i job. Il job Windows ha eseguito lo ZIP da un percorso Unicode/con spazi, con `PATH` limitato al sistema, e ha superato self-test e soak su entrambi i backend. In 110 campioni offscreen ha osservato `platforms/qoffscreen.dll`, Qt6Core/Gui/Widgets e altri moduli inventariati; in 109 campioni Windows ha osservato `platforms/qwindows.dll`, `styles/qmodernwindowsstyle.dll`, Qt6Core/Gui/Widgets e altri moduli inventariati. Entrambi i registri dei percorsi esterni erano vuoti. L'inventario statico precedente continua a verificare 43 DLL/44 file PE e la chiusura degli import.

Questa osservazione completa il controllo dei caricamenti **campionati** durante due flussi sintetici. Non prova l'assenza di moduli transitori, i plugin caricati da altri flussi, il comportamento su Windows 10/11 puliti, l'intero codice incorporato nelle DLL o la conformità delle licenze. M0-02 e M0-06 restano parziali.

## English

In the extracted Windows ZIP test, `scripts/test-windows-package.ps1` samples process modules during `--soak-test=10s` with both Qt `offscreen` and `windows` backends, after removing MSYS2/Go from `PATH`. Every path beneath the bundle must occur in the 43-DLL inventory or be `webfence.exe`; the test requires Qt6Core/Gui/Widgets and the corresponding platform plugin. Paths outside the bundle and Windows directory are recorded for review. `Process.Refresh()` precedes each module read because [.NET documentation](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.refresh?view=net-10.0) specifies that process information may be cached.

The first attempt, [`18c223a`, run 35950725323](https://github.com/Matte2599/WebFence/actions/runs/35950725323), passed application tests but failed the Windows job because module sampling did not observe `qoffscreen.dll`. After adding `Process.Refresh()` and printing the observed inventory before assertions, [CI `a9a8e5c`, run 35951514939](https://github.com/Matte2599/WebFence/actions/runs/35951514939) passed all six jobs. The Windows job ran the ZIP from a Unicode/spaced path with a system-only `PATH`, and passed self-tests and soaks on both backends. Across 110 offscreen samples it observed `platforms/qoffscreen.dll`, Qt6Core/Gui/Widgets and other inventoried modules; across 109 Windows samples it observed `platforms/qwindows.dll`, `styles/qmodernwindowsstyle.dll`, Qt6Core/Gui/Widgets and other inventoried modules. Both external-path lists were empty. The earlier static inventory still verifies 43 DLLs/44 PE files and import closure.

This completes a check of **sampled** dynamic loads during two synthetic flows. It does not prove absence of transient modules, plugins loaded by other flows, behavior on clean Windows 10/11 machines, all code embedded in the DLLs, or license compliance. M0-02 and M0-06 remain partial.
